The process gap was treating a claim about requested writes as a filesystem correspondence theorem.

Decided on the owner's behalf: replace the table's truncating writer with exclusive creation, accepting an already existing file only after reading equal text. This preserves the supported equal-text shared-file case. A differing text fails the required copy and the existing reader contract prevents a build. No new path-normalization algorithm is introduced.

The highest available rung for non-overwrite is construction: the only write handle is obtained with Lean's `Mode.writeNew`, documented in `Init/System/IO.lean` as `O_EXCL` and as failing for an existing file. Physical aliasing cannot be represented statically by Lean path strings; the filesystem owns that identity. The equality branch is an invariant-derived guard, proved of its actual IO definition. A successful copy must install its requested text and preserve every previously present text, over an arbitrary filesystem view with no injectivity premise for path keys. An execution correspondence theorem must carry that property to each full-run consumer; the other primitive calls retain their existing obligation to preserve copied inputs.

Boundary challenges: different spellings, Unicode aliases and shared paths must never permit a truncating write; equal-text aliases must remain successful; failed creation, read, write or flush must not produce success; a failed writer must prevent every later consumer. The proof must derive the writer contract from Lean's primitive calls, rather than assume the contract for Regula's writer.
